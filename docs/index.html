Quickstart Onboarding

Connect Your Infrastructure in 60 Seconds

Choose your deployment flavor. The sensor auto-discovers network interfaces and streams encrypted telemetry back to your NDAP SaaS tenant.

1. Install and start NDAP Sensor service on Ubuntu/Debian/RHEL:
curl -sSL https://get.ndap.cloud/install.sh | sudo bash -s -- --api-key "ndap_live_usr_99a8b"

The installer registers ndap-sensor.service under systemd, configures automatic restart on crash, and binds to active interfaces with CAP_NET_RAW.

Deploy sensor container in host network mode:
docker run -d --restart=always --net=host --cap-add=NET_ADMIN -e NDAP_KEY="ndap_live_usr_99a8b" ghcr.io/rohit30confluence/ndap-sensor:latest
Deploy across all Kubernetes nodes via Helm:
helm repo add ndap https://charts.ndap.cloud && helm install ndap-sensor ndap/sensor --set apiKey="ndap_live_usr_99a8b"
Agentless VPC Mirroring (AWS VPC Mirror / GCP Packet Mirroring):

Configure your Cloud Provider to forward mirrored VXLAN/Geneve packets directly to your private NDAP Cloud Ingest endpoint:

collector.us-east-1.ingest.ndap.cloud:4789 (VXLAN VNI: 1000)

Common Inquiries

Frequently Asked Questions

Everything you need to know about adopting NDAP as a managed Network Detection SaaS.

How does NDAP differ from traditional tools like Zeek or Snort? +
Legacy tools like Zeek or Snort are heavy, complex monoliths written in C/C++ requiring dedicated servers, manual rule compile scripts, and constant maintenance. NDAP is written in pure safe Rust, consumes less than 25MB RAM, and handles wire decoding, flow tracking, automated cloud threat feed correlation, and real-time WebSocket feeds out of the box with zero compilation hassle.
Will deploying the sensor cause latency or slow down our network? +
No. The NDAP sensor operates in passive tap/promiscuous mode or cloud VPC mirroring mode. It reads a copy of network packets asynchronously without sitting inline, meaning it can never introduce latency, throttle throughput, or interrupt production application traffic.
Are sensitive customer payloads transmitted to your cloud? +
No. In our default Zero-Payload Privacy mode, the edge sensor only extracts Layer 3/4 headers, conversation metrics, and protocol metadata (e.g. DNS domain names, HTTP methods/URIs). Raw customer payload bytes are never stored or transmitted, ensuring complete compliance with HIPAA, GDPR, and PCI-DSS requirements.
Can I customize detection rules or integrate our proprietary IOC feeds? +
Yes. Pro and Enterprise customers can upload custom CSV/JSON threat feeds, configure Sigma-lite rules, and author out-of-process Python plugin detection scripts using our Python SDK with full process isolation.
Can I cancel or change my plan anytime? +
Yes. Subscriptions are billed on a flexible monthly or annual basis. You can add or remove sensors and upgrade or downgrade tiers at any time directly through your account settings.
